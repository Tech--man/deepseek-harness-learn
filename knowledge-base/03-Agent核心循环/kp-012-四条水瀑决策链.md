# 四条水瀑决策链

## 一句话定义
Agent 循环把所有"可改变行为"的时机做成 **waterfall（around 中间件）** 事件：`agent/pre-step`（准入）、`agent/request`（路由构建）、`agent/request-error`（重试决策）、`system-prompt/assemble` + `tools/pre-execute | tools/execute | tools/post-execute`（组装与工具管线）——监听者包装 `next()` 或短路返回，返回值即权威。

## 为什么重要
这是 dsh 的插件面"控制流 API"。压缩、审批、技能注入、请求改写、失败重试……全部通过在这几条链上排队实现，内核对这些特性一无所知。

## 前置知识
kp-007（waterfall 语义）、kp-010（turn flow）。

## 核心概念：四链各自的决策

| 链 | 时机 | 监听者可做 | 典型居民 |
|---|---|---|---|
| `agent/pre-step` | claim 之后、step 之前（**唯一在请求派生前**） | `reject` / `enter({messages, startsRequestSeries?})` / `cancel` | compaction 压力触发、skill 注入、pre-step 防线 |
| `agent/request` | prepareCall 之前 | 改写路由 config（provider/model/tools…）；**不能改消息**（core.md:949） | 路由策略、遥测标注 |
| `agent/request-error` | 一次尝试结算失败后 | `{kind:'retry'}` 或保留原错误 | compaction 溢出恢复、自定义退避 |
| `tools/pre-execute → execute → post-execute` | 每个工具调用的三段 | pre: allow/deny/**ask**/cancel；execute: around（超时/重试）；post: accept/block | 审批、guard、结果裁剪 |

另有 `agent/turn-stopping`（serial，无 next()）——自然停止前的最后检查点，可排水 steering。

## 原理 / 机制

**统一包装**（dispatch.ts:120-146）：agent 域事件经 `agentEvents(ctx, agent)` 包装——payload 自动融合 `agent` 字段，carrier = `scopeTarget(agent 的 scope)`（scope 过滤，kp-022）。`emit` 单监听器失败容错；`serial` 按序 await；waterfall 组合结果。

**包装传递的礼仪**（docs/architecture.md:118-119）：包装 `next()` 的监听者 **必须透传下游的 `messages` 与 `startsRequestSeries`**，除非有意替换——否则会悄悄吃掉别人声明的"新请求序列"标记：

```ts
ctx.on('agent/pre-step', async (ev, next) => {
  const decision = await next()
  if (decision.reject) return decision
  return { ...decision, messages: dedupe(decision.messages) }  // 保留 startsRequestSeries
})
```

**预请求 vs 请求中**：`agent/pre-step` 是唯一在请求派生前完整的 waterfall（core.md:337）；`agent/request` 之后进入"同步准入"（system/users 落日志），此时再取消 = 什么都不提交。

## 直观类比
四条链像 **海关的四个关卡**：pre-step=入关审查（可以整批拒绝、可以加塞申报单）、request=出境航班登记（改航班但不能改乘客名单）、request-error=航班取消后的改签窗口、tools/*=行李的托运/安检/提取三段。每一关都有"盖章放行"（next）与"直接拦截"（return）两种姿势。

## 实例 / 案例
compaction-basic 的居民证（对照 kp-020）：
- `agent/pre-step`：每步边界测压力，达标则先压缩再放行；
- `agent/request-error`：只认 `CONTEXT_WINDOW_EXCEEDED`，返回 `{kind:'retry'}` 触发开放 step 内重试。

审批系统的居民证：`tools/pre-execute` 返回 `ask` → approval 服务弹出 `allowed-once`。

## 常见误区
- **在 agent/request 里改消息**：不允许——消息已是日志事实（model-visible means logged），路由层只能动 config；
- **pre-step 里做昂贵工作不设 signal**：监听者应尊重 `ev.signal`，否则取消会迟到；
- **以为瀑布顺序可预测地等于包激活顺序**：顺序 = 同一 ctx 上的注册顺序，跨层组合时应显式 `prepend` 或让文档说话。
