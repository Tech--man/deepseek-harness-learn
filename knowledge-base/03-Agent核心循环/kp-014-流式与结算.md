# 流式与结算

## 一句话定义
每次模型尝试要么以 `assistant/message` 结算（进模型历史，嵌入精确压缩流），要么以 `assistant/attempt` 结算（log-only，保留失败/取消/流错误现场）；直播通道 `agent/assistant-stream` 是进程内瞬态帧，端帧只在对应 durable 事件落定后发出。

## 为什么重要
"直播"与"录像"分离是 dsh 事件体系的核心设计：UI 增量走直播（快、可丢失），重放/审计走录像（慢但永不丢）。所有下游（fork、transcript、遥测）都从 durable 结算派生——统一且可验证。

## 前置知识
kp-013。

## 核心概念

| 通道 | 事件 | 消费者 | 可靠性 |
|---|---|---|---|
| 直播 | `agent/assistant-stream`：start → chunk* → end | Web Session-follow 适配器（唯一远程消费者） | 进程内瞬态，进程死即失 |
| 结算 | `assistant/message`（成功，含 content-less 与 max-tokens） | deriveMessages → 模型历史 | durable |
| 结算 | `assistant/attempt`（失败/重试/取消/流错误，**未产生 surface message**） | 重放/审计 | durable，log-only |

## 原理 / 机制：AssistantStreamAttempt 协议（assistant-stream.ts:18-140）

```text
start 帧   在首个 chunk 前发出
chunk*     每块先写 durable 累加器，再 emit chunk 帧（顺序保证）
end 帧     只在 durable 事件落定【后】发出
           outcome = {kind:'committed', eventType, seq} | 'abandoned'
attemptId = `${sessionId}:${attempt}`
```

**流异常分支**（agent.ts:428-469）：
- 已 start 且 aborted：有可见前缀 → `assistant/message {interrupted: true}`（已交付内容不丢）；无前缀 → `assistant/attempt {stream}`，然后重抛；
- finish=error/aborted：append attempt → waterfall `agent/request-error`（重试决策）；
- **硬进程死亡**：settlement 之前 → 无 durable attempt 流（有意的：半截录像没有价值）。

**成功结算内容**（:495-512）：blocks + `source{provider,model,replayState}` + usage + **精确压缩带时流**（嵌入 message，重放时逐块回放）。`replayState` 是 adapter 私有信封（如 DeepSeek 的 reasoning signature），跨 adapter 会被剥离（`forAdapter`，llm/index.ts:992-1006）。

## 直观类比
两通道像 **电视台直播 + 新闻成片**：直播帧（chunk）实时好看但不可靠；成片（message/attempt）当晚入库、带完整字幕（流）；直播中断（进程死）不留半成品——观众只信成片。attempt 是"花絮/事故录像"：不上正片（不进模型历史），但留存备查。

## 实例 / 案例
- Web UI 的打字机效果来自 `agent/assistant-stream` chunk 帧；刷新页面后重放的是 `assistant/message` 嵌入流（ kp-027 数据流）；
- `max-tokens` 完成（stop reason）也是一次成功结算——空 content 不进派生历史，但事件仍记录（agent-lifecycle.md）。

## 常见误区
- **以为 assistant-stream 需要自己持久化**：不需要也不该——它是瞬态；要历史就监听 `session/event`；
- **以为 attempt 进上下文**：log-only，只供重放；重试的新尝试才是下一个 message；
- **以为 end 帧先于落库**：顺序刻意相反——先 durable 后 end，保证 end 帧的 `outcome.committed.seq` 可信。
