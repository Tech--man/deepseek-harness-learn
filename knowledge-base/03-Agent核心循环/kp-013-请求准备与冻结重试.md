# 请求准备、冻结与重试语义

## 一句话定义
每次 step 内，循环先 `prepareCall()` 拿到绑定的 `PreparedLlmCall`（一次性、携带能力声明），再以日志为源 **派生并深冻结** 请求；失败重试只重做 prepare+build，不重复组装、pre-step、用户准入——"同一份渲染组装，多次尝试"。

## 为什么重要
这段是"日志真相源"原则的最密集落点：请求从日志来、冻结保证不可变、重试保证可解释。理解它，才能理解为什么 assistant/attempt、KV-cache 友好提示、压缩重试这些设计都能自洽。

## 前置知识
kp-010、kp-012、kp-016（session log）。

## 核心概念

| 概念 | 内容 |
|---|---|
| `PreparedLlmCall` | `{config, preparedCall}`：冻结 config、retryPolicy、`adapterDefaults`、context/inputModalities/`systemPromptUpdate`/`toolUpdate` 能力声明；**只能 dispatch 一次**（llm/index.ts:964-973） |
| 冻结证据 | `canonicalHeader` 归一（空 tools/空 adapterDefaults 删除）→ `deepFreeze(header)`；消息对象每 agent 只深冻结一次（WeakSet，agent.ts:119-120,653-659） |
| 请求构成 | `header.config + deriveMessages() + header.tools`，**无独立 `system` 字段**（:661-668；`validateSessionEventData` 禁止 header.system） |
| request/header | `{header, reason: initial\|resume\|change\|series, startsSeries?}`——只在首请求/信封变化/显式新序列/表面替换时记录，其余继承（README.zh:93） |

## 原理 / 机制：重试的精确边界

```text
step() 内 while(true)：                # 每次模型尝试一轮
  renderPrompt(assembly)               # 循环外算一次（:388-389）
  首轮(firstAttempt)：
    append system/message  +  append user/message（只此一次，:389-407）
  prepareRequest()                     # agent/request 瀑布 → prepareCall
  buildRequest()                       # 记 header/context → 派生冻结请求
  stream → 成功? assistant/message : assistant/attempt
  失败 → agent/request-error → {kind:'retry'} → continue（回到 prepareRequest）
```

- **不重复**：assembly、`agent/pre-step`、`user/message` 准入（agent-loop/README.zh:119 明文）；
- **会刷新**：header 比较用实时 `session.requestHeader()`——重试期间发生的 compaction 能被看到；
- **startsRequestSeries 三个来源**（agent.ts:289-297,393-397）：pre-step 决策声明；`surface.contentGeneration` 变化（表面替换/图片省略）；prepared 路由未声明 `toolUpdate` 而 tools 变化。

**取消语义**：`agent/request` 与 `prepareCall()` 两个异步阶段中取消 → system 与 users 都不提交（"cancellation commits neither"，docs/architecture.md:100）。

## 直观类比
prepareCall 像 **给外发送快递前打印面单并封箱**：面单（能力声明：能不能带图、能不能中途换工具）决定能装什么；封箱（冻结）后任何修改都要开新箱；重试是 **重新打印面单换一家承运商**，但箱子里的货物（渲染组装）不变。

## 实例 / 案例
- 图片降级：路由声明 `inputModalities` 不含 image，请求装配期把图整体投影为文本占位（llm/index.ts:1070-1074）——发生在 buildRequest 阶段，所以重试无需重判；
- 压缩恢复（kp-020）返回 retry 时，重试会用新 surface generation 重算 startsRequestSeries。

## 常见误区
- **以为重试会重新触发 pre-step**：不会；重试只重做 prepare+build；
- **以为 header 每步都落盘**：只在 reason 变化时记录；连续步骤继承最新 header（README.zh:93）；
- **把 `adapterDefaults` 当请求字段**：它标记"哪些字段是 adapter 补全的"，用于跨代比较而非发送。
