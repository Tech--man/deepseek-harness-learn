# 多智能体：subagent / continuable / teams / goal / Ralph

## 一句话定义
dsh 的多智能体面分四层：**subagent seam**（one-shot 与 continuable 两形态，多 provider 注册）、**agent teams**（实验性 implicit-root 团队：roster + 持久信箱 + 任务 DAG）、**goal**（同会话持久目标 + goal round + 进程内 activation）、**Ralph loop**（固定前台脚本循环，每轮 fresh 子代理 + 有界 handoff）——四种编排各管一个时间尺度。

## 为什么重要
"多 Agent"是个被滥用的词；dsh 把它拆成四个语义精确的机制，避免了"什么都是 agent"的泥潭。 glossary 甚至专设词条划清 goal 与 Ralph 的边界。

## 前置知识
kp-009（创建事务）、kp-022（scope 隔离）。

## 核心概念

**subagent**（subagent.md）：
- 结构 = Service Definition `ctx.subagents` + Providers（spawn/fork 进程内；acp/codex/claude-code/dsh-sdk 外部）+ 模型侧工具（`subagent` 工具 + 全局控制工具 send_message/interrupt_agent/list_agents）；
- **one-shot**：`start(name, req) → SubagentRun{id, result: Promise<SubagentResult>, dispose}`；能力标志（outputSchema/depthLimit/toolFilter/persona）在 start 前校验，缺则 `UNSUPPORTED_CAPABILITY`；`stopReason ∈ completed/aborted/error/max-tokens/refusal`（merge-extensible）；
- **continuable**：一个持久 child Session + 至多一个进程内 **Activation**（驻留期，可执行多个 FIFO 回合）；`sendMessage()` 仅允许直接父/直接子；目标 running→就近 step steer、waiting→唤醒、无 Activation→**cold resume**；
- **深度**：durable `SessionHeader.delegationDepth` 与 runtime `subagentDepth` **取较大者**为权威；绝对上限 `request.maxDepth`；
- **继承**：新 flat scope，不继承父注册；fork provider 经 `seed` 注入"平衡的已完成回合前缀"（截至最后一个 turn/end）；权限继承规则：Auto/Full-access 父附加捕获的 preset，Read Only/Workspace Write 子强制 `approval: never`。

**agent teams**（experimental/agent-team，agent-team.md）：
- implicit-root：`TeamId` 就是根 SessionId；成员 roster `provisioning → active|failed`；
- **持久信箱**：消息先存 `TeamMessageSnapshot`、目标 durable 落地后才 ack；恢复时 queued-minus-delivered 即信箱；投递一律 Steer；
- **共享任务 DAG**：`TeamTaskSnapshot{revision CAS, status, ownerId, blockedBy[]（无环校验）, writeScopes[]（advisory 前缀非锁）}`。

**goal**（goal.md）：
- durable 层：`GoalPhase = active|paused|blocked|complete`，每次变更是完整快照 `goal/change`（或 clear tombstone）；
- **goal round**：每个被接纳的 goal 消息回合带正序号 `GoalMessageSource{goalId, revision, round}`；重放拒绝跳号/旧 revision/stopped phase/超 cap；
- **activation（进程内，永不持久化）**：`armed/disarmed`——`create` 即 arm；`disarm` 只移除续跑授权不改 durable 状态；之后需人工 `resume` 重新记录 activation edge。**这是"自动续跑必须人授权"的安全设计**。

**Ralph loop**（tool-ralph/README.md）：
- 固定前台脚本循环：每轮 **fresh 子代理**（无父对话、无历史子会话 seed），只收"不可变 objective + 当前轮次/上限 + 上一轮有界 report"；
- **共享 workspace 是跨轮记忆**；handoff = `{status: continue|complete|blocked, summary, evidence, next steps, blocker}`，非法/超长直接失败；
- `subagentProvider` 经 `WorkflowStartRequest` 注入且必须 `inheritsParentContext:false` + 支持结构化输出——固定脚本无法改路由；`maxRounds` 默认 256；
- 与 goal 的区别（glossary）：goal=同会话自动续跑（同一 Agent 接 user 回合）；Ralph=每轮换新 Agent 的前台工作流。

## 直观类比
- subagent one-shot = **外包一次性任务**（验收后走人）；
- continuable = **常驻外聘顾问**（有工位，可直接对话，冷启动=重新入职）；
- agent teams = **虚拟部门**（花名册、内部邮件、任务看板）；
- goal = **同一员工的 OKR**（持续推进、可暂停可封存，自动加班要先授权）；
- Ralph = **流水线夜班**：每班次新人只看交接单（handoff），工作台（workspace）是共享的。

## 实例 / 案例
- `listDescendants()` 递归预序列出全部后代（parentId+depth），读的是 `subagentCatalog` 投影——不打开子日志；
- workflow 引擎每 context 只允许一个实现（对比 subagent 多 provider registry，workflow.md:5）；事件 `workflow/start|phase|log|agent-start|agent-end|end` 为 observe-only。

## 常见误区
- **以为子代理继承父的工具/人格**：flat scope 设计 + seed 日志前缀，仅此而已；
- **把 goal 的 activation 想成持久状态**：刻意进程内——resume/fork 后必须人工重新授权；
- **把 Ralph 当通用循环调度器**：glossary 明确它只是"模型侧工具策略组合"，不是 scheduler。
