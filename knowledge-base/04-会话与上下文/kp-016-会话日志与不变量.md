# SessionEvent 追加日志与不变量

## 一句话定义
会话是一份 **追加式事件日志**（`ctx.sessions`）：模型看到的一切都先作为 `SessionEvent` 落日志、再从日志投影历史（"model-visible means logged"）；对已落事件的"改写"只能以 **surface 替换**（带 sourceEventSeqs 的遮蔽）表达，历史永不被改。

## 为什么重要
这是整个 harness 的真相源：fork、resume、transcript、遥测、压缩、UI 全部从它派生。一旦理解这条不变量，很多"奇怪"的设计（请求无 system 字段、重试不重复准入、投影注册）都会变得必然。

## 核心概念

**Durable session events 家族**（session/src/types.ts:281-428）：

| 事件 | 说明 |
|---|---|
| `turn/start · turn/end · step/start · step/end` | 循环骨架 |
| `system/message · developer/message · user/message · assistant/message` | 消息面（assistant 嵌入压缩流） |
| `assistant/attempt` | 失败尝试结算（log-only） |
| `tool/call · tool/result` | 工具对（result 以 sourceEventSeqs 引用 call） |
| `request/header · request/context` | 请求信封与快照 |
| `session/end-seed` | 继承切点标记 |
| 插件扩展 | `agent/inbox/spliced`、`compaction/*`（log-only）、`tool/ptc-dispatch*` 等 |

**seq 契约**：`seq = log.length` 连续递增；append 同步提交，观察者失败被容错（index.ts:722-773）。

**Surface（表面）**：模型可见的节点集合。五种 surface 事件（system/developer/user/assistant message + tool/result）；`surfaceOp: 'append' | {op:'replace', startSeq, endSeq}`——替换 **必须** 把被遮蔽的全部节点列入 `sourceEventSeqs`（types.ts:462-478）。`contentGeneration`（替换+消息投影）与 `replaceGeneration`（位置替换）两个代数是 kp-013 重试判据。

## 原理 / 机制

**不变量清单**（每条都可在源码找到对应校验）：
1. 请求 = `header.config + deriveMessages() + header.tools`，无 `system` 字段（agent.ts:661-668；surface.ts:210 禁止 header.system）；
2. 每次结算的模型尝试恰一个 durable 事件（message 或 attempt，kp-014）；
3. 新的模型可见输入必须新增 session 事件；改消息内容必须注册 **纯消息投影**（subsystems/session.md）；
4. 插件修改既有消息 → `dsh-session-projection` 注册 fold；detached reader 显式带同样定义。

**投影注册表**（session-projection/src/index.ts:199）：`{key, stateSchema, init, apply, stateVersion, wire}` 的纯 fold 定义，增量折叠提交事件；host 用 `stateOf()` 读类型化状态，carrier 用 `snapshot()` 批量裁剪给客户端。agent-loop 注册 `turnBoundary`（turn 号源）与 `inbox` 两个共享投影（agent-loop/src/index.ts:57-95）。

## 直观类比
会话日志像 **区块链账本**：只追加、不改历史；"修正"是记账式冲正（replace + 引用被冲正的 seq）；投影像 **会计报表**——每次都从账本增量推导，报表可以缓存（derivedGeneration），账本永远是唯一事实。

## 实例 / 案例
- 压缩把旧历史折叠：`compaction/summary → user/message(replace, sourceEventSeqs=[被折叠节点…]) → compaction/end`（kp-020）；
- fork：以 `turnBoundary` 投影找边界，`seed` 携带截断日志 + `meta.seedLength` 标记继承范围（architecture.md 扩展表）。

## 常见误区
- **把 session/event 当 UI 总线滥用**：它是 durable 事实流；UI 增量优先 live `agent/*`；
- **以为 replace 是"编辑原行"**：物理上原事件原样保留，replace 只是逻辑遮蔽（这才有无损迁移与审计）；
- **以为消息内容可随时注册投影改掉**：投影必须"纯"（同输入同输出），且 detached reader 要显式复刻定义——这是强约束不是建议。
