# 上下文压缩 compaction

## 一句话定义
压缩是一个 **插件实现的标准接缝**（`compactIfNeeded/compactNow/compactRegion` 三操作）：dsh-compaction-basic 在 `agent/pre-step` 测压力、在 `agent/request-error` 接溢出；恢复走"先剪枝、再摘要"两步，且只有 surface replaceGeneration 前进才返回 retry；整个过程以 `compaction/start…end` 日志标记对为锁。

## 为什么重要
长会话必然撞 context window。dsh 展示了"压缩"如何作为一个可替换插件嵌入循环——不碰内核一行代码，还能通过日志锁保证崩溃安全。

## 前置知识
kp-012（水瀑链）、kp-016（surface replace）。

## 核心概念

**seam 三操作**（compaction/src/types.ts）：
| 操作 | 何时用 |
|---|---|
| `compactIfNeeded(agent, 'pressure' \| 'context-overflow')` | 自动触发 |
| `compactNow(agent, …)` | 用户/插件显式 |
| `compactRegion(agent, {startSeq,endSeq}, …)` | 显式范围 |

**日志锁**（log-only 事件序列）：

```text
compaction/start (turn 归属或 null)
  compaction/summary
  user/message (op:'replace', sourceEventSeqs=[被折叠节点…])   ← 唯一 surface 变更
compaction/end
```
崩溃留下未配对的 start = busy 信号——锁的实现就是日志本身。

## 原理 / 机制

**压力触发**（compaction-basic/src/index.ts:158-176）：
- 挂 `agent/pre-step`，每步边界测量；
- `ctx.tokenMeter` 测最新 durable 路由请求信封；`ctx.llm.resolveModelInfo` 解析 contextWindow；
- `messageBudget = contextWindow - reservedCompletionTokens`，再扣 `headroomTokens`（默认 65_536，config.ts:75-77）为压力阈值；
- 测量失败仅 warn，turn 继续（压缩坏了不能打死会话）。

**溢出恢复**（:190-234）：
- 挂 `agent/request-error`，只认 `CONTEXT_WINDOW_EXCEEDED`；
- 每 agent 计 `maxOverflowRetries`（一次成功 `assistant/message` 即重置，:184-188）；
- overflow 绕过阈值与保留尾策略（retain=0）强制缩减；
- **返回 `{kind:'retry'}` 当且仅当 `surface.replaceGeneration` 前进**——否则原错误保持权威（不空转）。

**两步恢复**（:289-301）：
1. 可选 prune：`toolResultPruner.pruneSession()`——模型无关的大结果替换，走 `compaction/prune` shadow-price 协议记录；
2. `selectCompactableRange`（region.ts:117-150）：跳过 node 0 的 system 头；从尾部按定价累积到 `retainTokens/retainRatio`；**回退到工具配对平衡点**（tool-pairing.ts 禁止切断未回应的 call/result 对）；
3. 摘要：一次性 `ctx.llm.stream()`，**前缀复用会话自身的 system/tools/messages**——保 KV cache。

## 直观类比
像 **衣柜收纳**：每周检查（pre-step 压力）发现塞不下就提前整理；某天门关不上（overflow）才做强制整理。整理分两步：先扔吊牌（prune 无关紧要的标签），再打包装箱（摘要折叠旧区）；装箱有清单（sourceEventSeqs），箱子上有封条（start/end 锁）——中途搬家（崩溃）也能发现"有箱没封"。

## 实例 / 案例
计算一次触发：128K 窗口 − 8K 保留完成 − 64K headroom = 56K 触发线；当前请求信封 57K token → pre-step 阻塞（在准入前）先压缩 → 折叠尾部历史 → 放行。

## 常见误区
- **以为压缩是循环内置功能**：它是插件；`ctx.tokenMeter` 也是独立服务（token-meter 包）；
- **以为 overflow 重试会重新走 pre-step**：重试在开放 step 内（kp-013），只重做 prepare+build——所以必须靠 replaceGeneration 前进来证明"这次不同了"；
- **以为摘要随便丢**：工具配对平衡点保证 call/result 一起折叠或一起保留，模型历史永远合法。
