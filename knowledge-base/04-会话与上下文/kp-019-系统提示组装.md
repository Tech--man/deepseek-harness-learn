# 系统提示组装与 surface node 决策

## 一句话定义
提示词由 **sections + variables + tool schemas** 组装（scoped 同名遮蔽全局、order 显式排序、`system-prompt/assemble` waterfall 可拦截），然后以"提示词即表面节点"的策略落成 `system/message`：能 in-history 的路由走追加（KV-cache 友好），不能的或新序列走"记录式空替换 + 头节点重写"——旧提示词永远干净地退出模型视野。

## 为什么重要
系统提示是 Agent 的"人格与规则"，其更新策略直接影响成本（KV cache 命中）与正确性（旧指令残留）。dsh 的方案同时优化两者，是读懂 `request series` 语义的最终章。

## 前置知识
kp-013（series/冻结）、kp-016（surface）、kp-018（投影）。

## 核心概念

**组装管线**（system-prompt/src/index.ts:558-635）：
1. 解析变量（scoped 最近者赢；`{{var}}` 未知即抛错）；
2. sections 合并排序：`order` 升序 + 名次序；集中式序号表（IDENTITY -1000、TOOL_* 1000~3000、MCP_SERVERS 3100、TOOLS_SDK 5000、STRUCTURED_OUTPUT 9900…）；
3. 收集 tool provider 的 schemas 与 knownNames；`orderTools` 要求恰好一个 rest 标记 `<unlisted-tools>`（:191-229）；
4. 跑 `system-prompt/assemble` waterfall；
5. **complete section 恢复**：注册了 `complete:true` 的 section 在瀑布后恢复为唯一 section——监听者无法替换整个提示词（:629-634）。

**注册 API**：`ctx.systemPrompt.section()/context()/variable()/tools()/suppressRuntimeContext()`，全部经 ScopedLayers（scoped shadowing 与 kp-022 同机制）。loop 注册 `provider/model/cwd` 三个变量。

## 原理 / 机制：SystemPromptProjection.project（runtime-context.ts:65-111）

```text
决策输入：
  inHistory     = prepared call 声明 systemPromptUpdate:'in-history'
  startsSeries  = kp-013 三来源
  rendered      = 本次渲染文本

分支：
  追加（inHistory 且延续序列且 rendered 非空且 ≠ latest.text）
    → append 新 system/message 到缓存历史之后
  归一（无 in-history / startsSeries / rendered 为空）
    → 所有活跃非空后继节点做【有日志记录的空内容替换】
    → 头节点（node 0，首个提示词即预留）按需重写
    → 空渲染 = 清空全部活跃节点（模型看不到旧指令）
```

细节：首个提示词（即使为空）先追加为 node 0——给"头部重写"留位；"休眠的空尾节点"不决定有效文本，无需重复替换（省事件）。

## 直观类比
像 **白板会议纪要的两种更新法**：支持"增量板书"的会议室（in-history 路由）直接在白板后段追加更新——前文板书不用重写（KV cache 命中）；不支持增量的小会议室每次换白板（新 series）或整板擦除重写（空替换），且擦除动作要记录在案（"有日志记录的替换"）——没人能看到被擦掉的旧规则。

## 实例 / 案例
- persona 插件注册 section（order 0 前后）+ 用户 patch 改 `system-prompt` 行的 persona 配置（web-app patch 覆写 base 行）；
- 工具增删在有能力路由上以 `tool-addition/tool-removal` 块进历史（`toolUpdate:'in-history'`），否则 `developer/message`（agent.ts:618-632）——两档策略与 systemPromptUpdate 对称。

## 常见误区
- **以为系统提示是一个固定字符串**：它是组装产物 + 表面节点策略的动态结果；
- **以为 empty rendering 是"保持原状"**：恰恰相反——清空全部活跃节点（防旧指令残留是硬要求）；
- **在 assemble waterfall 里直接换掉整个 sections 数组**：complete section 机制会恢复权威节——想改走注册 API。
