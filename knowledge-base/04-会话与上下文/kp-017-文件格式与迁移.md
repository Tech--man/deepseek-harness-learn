# 会话文件格式：JSONL vN、zstd、generation 与迁移链

## 一句话定义
会话落盘为分代 JSONL（`session.jsonl` 为 v0，此后 `session.vN.jsonl`，当前 `SESSION_FORMAT_VERSION = 4`），zstd 分帧压缩、帧带校验和；磁盘保留不可变历史 generation，读取只选最高 canonical 代，写入通过"编码→校验→独占发布后继"完成，`vN→vN+1` 迁移包首尾相接成静态目录链。

## 为什么重要
Agent 会话是长期资产（可能跨月、跨版本软件）。dsh 给出了一套少见的严谨方案：不可变文件 + 显式版本 + 有界迁移，兼顾"永不丢"与"格式可演进"。

## 前置知识
kp-016。

## 核心概念

**磁盘布局**（persistence-jsonl/README"磁盘布局"）：

```text
<root>/<--normalized-cwd--|_no-cwd-->/<encoded-id>/
  session.jsonl[.zstd]     # v0
  session.v1.jsonl[.zstd]  # v1（v2/v3/vN 同理）
```

**版本政策**：单调整数版本号（无 major/minor）；只有 header 形状、事件信封、核心事件语义、surface 机制变化才 bump；普通新增事件类型靠 `SessionEvent.ignorable` 兜底（types.ts:68-89）。

**zstd 物理编码**：一帧 = header 行 或 一个 durable append 批次；帧带校验和；`sourceEventSeqs` 无损压缩为 `[start,end]` 区间对（≥3 连续才压缩，seq-ranges.ts）。`compression:'none'` 时为纯文本行；一个 root 只允许一种编码。

## 原理 / 机制

**generation 规则**（architecture.md"Session log"节）：
- `stat/list` 只扫描目录取数值最高 canonical 代，翻译其 header（**不读正文、不发布后继**）——列表页因此廉价；
- 读 open：单遍解码静态相邻迁移链后返回内存结果；
- 写 open：编码 → 校验 → **独占发布** 版本命名的后继文件（与源文件并列），源文件逐字节不变；已提交的 generation 路径永不重命名/替换/删除。

**迁移链**（v0→v1→v2→v3→v4，各自一个包）：
- v0→v1：逐行规范化；
- v1→v2：把顶层 `assistant/chunk` 嵌入对应 `assistant/message`、补记 attempt、密集重映射 seq（kp-014 决策的由来）；
- v2→v3：系统提示词从 header.system 提升为 `system/message`（kp-019 的 surface 前身）；PTC/预设名称规范化；
- v3→v4：提升工具结果、重命名 message source、为有证据的中断回合补 closers、补父目录事实（需子会话证据）。

静态目录 `dsh-session-format-catalog` 在模块初始化时校验链条完整无缺口——**profile 不能增删或重排迁移边**。

**修复规则**（kp-015 已述合成 closers；物理层）：不完整尾行丢弃；撕裂 zstd 帧只保留完整记录并截断撕裂字节；校验和/结构失败 = 损坏拒绝；已退役必需 PTC 标签等即使出现在畸形行之后也拒绝整个文件。

## 直观类比
像 **博物馆的修复学**：文物（generation）永不返工，修复以"并置新柜 + 标注来源"呈现；每个修复师（迁移包）只做一步且被编目（catalog 校验），修复流程（写 open）先在隔离台（临时文件）完成并检验后才入柜（独占发布）。

## 实例 / 案例
崩溃在写入中途：撕裂帧 → 下次 append 前截掉撕裂字节并持久重写恢复记录——文件回到"完整记录 + 干净尾巴"状态；若撕裂的是帧尾校验和，读取贡献完整部分。

## 常见误区
- **以为 v4 会重写所有旧会话**：迁移是读取时行为（读 open 单遍），写 open 才发布后继——老文件安然无恙；
- **以为 zstd 是整文件压缩**：按帧压缩，头部与批次独立成帧——这是能"只解码到断点"的前提；
- **以为版本号会有 v4.1**：设计上只接受整数 bump，小改动靠 ignorable。
